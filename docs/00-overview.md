## 2. 为什么是这个顺序

| 顺序 | 阶段 | 为什么不能跳 |
|---|---|---|
| 1 | 语料工程 | 预训练的每一步都在读 `train.bin`；语料错了后面全是白跑。**漏斗统计必须在这一步就存下来**，否则训练崩了无从归因 |
| 2 | 冒烟 20 步 | 用一个真实 config、真实数据跑 20 步，能同时验证：显存够不够、吞吐多少、loss 是否从 `ln(V)` 开始下降 |
| 3 | 续训验证 | 长跑一定会中断（关机/抢占/OOM）。**在长跑之前**证明"续训能接上"，否则 2 小时的训练可能白费 |
| 4 | 125M 长跑 | 小模型跑通全流程、拿到可用的 base，同时是 SFT 的初始化 |
| 5 | 360M 长跑 | 同一份数据、同一套代码，只改 config——验证"扩规模"这件事本身是否顺畅 |
| 6 | SFT | 把 base 变成"会回答问题"的模型 |
| 7 | 记忆原型 | 把模型接进一个真实可用的 CLI，验证它作为"组件"而不是"玩具"的价值 |

> 关键判断：**续训验证放在长跑之前**。多数教程把它放在最后当"加分项"，但那时的失败成本已经是最高的。

## 3. 三个任务的验收（可测量）

| 任务 | 验收项 | 目标 | 本项目实测 |
|---|---|---|---|
| 02 | 篇数 / tokens | 71,224 篇 / 111.86M | 71,665 篇 / 112.50M |
| 02 | 分词质量 | chars/token 1.5–1.7 | 1.568 |
| 01 | 125M 吞吐 | 18.8k tok/s（5070 Ti） | **114.3k tok/s**（4090D） |
| 01 | 峰值显存 | ≈12 GiB | 11.15 GiB（reserved 12.12） |
| 01 | 续训偏差 | < 0.05 | **0.0100**，指纹 60/60 一致 |
| 01 | 两个规模 | 125M / 360M | 125.75M / 360.40M |
| 03 | SFT 样本 | ≈2.4 万 | 24,000 |
| 03 | 记忆 | 压缩 / 持久化 / 检索 | SQLite + FTS5，见 05 章 |
