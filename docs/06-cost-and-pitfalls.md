# 06 · 成本与踩坑：¥19 里有多少是学费

> 这一章不是"经验谈"，是**账单**。每个坑都标了它的价格。

## 1. 账单

| 阶段 | 墙钟 | 计费方式 | 金额 |
|---|---:|---|---:|
| 取数（并行 range + HF 镜像） | 30 min | 无卡模式 ¥0.1/时 | ¥0.05 |
| 语料工程（转换/抽取/清洗/去重/分词/打包） | 8 min | GPU ¥1.88/时 | ¥0.25 |
| 冒烟 20 步 | 2 min | GPU | ¥0.06 |
| `kill -9` 续训验证 | 5 min | GPU | ¥0.16 |
| 125M 预训练（699 步 / 343.6M tok） | **50.6 min** | GPU | **¥1.59** |
| 360M 预训练（456 步 / 224.1M tok） | **114.4 min** | GPU | **¥3.58** |
| SFT（24k 样本 / 2 epoch） | ~40 min | GPU | ¥1.25 |
| 记忆原型演示 | 5 min | GPU | ¥0.16 |
| **事故：实例空转** | **6 h** | GPU 全价 | **¥11.3** |
| **合计** | | | **≈¥18.4** |

**结论：有效计算 ≈¥7.1，学费 ¥11.3。**

## 2. 七个坑（按代价排序）

### 坑 1 · 实例空转 6 小时（¥11.3）

**现象**：夜里一次工具调用被中断，没有确认后台状态就结束了回合。第二天早上发现实例从 00:50 idle 到 06:44，GPU 利用率 0%。

**根因**：把"命令发出去了"当成"任务在跑"。中断发生在"起任务"和"确认任务"之间。

**代价**：6 h × ¥1.88 = **¥11.3**（占总花费 61%）。

**解法**（三选一，建议全做）：
1. 每次起长任务后立刻 `pgrep -af train.py` + `tail -3 logs/*.log` 确认；
2. 用**自动接力的链**：`chain.sh` 等 125M 结束自动起 360M、再自动起 SFT（本项目就是这么跑完的）；
3. 开 `--time-budget-min`，让任何一次运行都有上限，不会无限烧。

> 这一条是全书唯一"纯亏"的坑，也是唯一一条**跟技术无关**的坑。

### 坑 2 · 维基 dump 在 IDC 里被限速（差点 12 小时）

**现象**：`dumps.wikimedia.org` 单连接 9–80 KB/s，3.45 GB 要 12 h+；24 路并行只到 124 KB/s。

**根因**：跨境链路 + 单连接限速，与"服务器带宽"无关。

**解法**：换 HF 镜像的 `wikimedia/wikipedia` parquet（**5.7 MB/s**），并用同 schema 转换保持下游代码零改动。详见 [01 章](01-corpus.md)。

### 坑 3 · "无卡模式"不是"免费 CPU 机器"

**现象**：文档写"无卡模式 ¥0.1/时"，实际配置是 **0.5 核 / 2 GB 内存 / 0 GPU**。拿它跑 wikiextractor，一个 14 MB 的小 dump 要 45 秒，3.45 GB 要 3 小时以上。

**解法**：无卡只做**下载**；抽取/分词/打包必须上 GPU 机（16 核）。

### 坑 4 · 关机后 GPU 被抢走

**现象**：关机 10 分钟后再开机，提示 `该主机空闲GPU不足`（主机 GPU 空闲 0 卡）。

**根因**：按量计费实例**关机即释放 GPU**给别人租。

**解法**：
- 短任务别关机，直接跑完；
- 必须关机时，准备好「克隆实例」到同区域另一台有空闲卡的机器（本项目从 061 机克隆到 132 机）；
- 克隆面板里**系统盘和数据盘都要勾**。

### 坑 5 · 克隆时没勾数据盘（重下 1.5 GB）

**现象**：克隆出来的实例 GPU 正常，但 `/root/autodl-tmp/work` 不存在。

**根因**：克隆对话框里"数据盘"复选框默认**不勾**，而且 Element-Plus 的复选框要点到内部 `input` 才真正生效。

**解法**：勾选后确认 class 里有 `is-checked`；或者干脆把数据全部重新下载（本项目后来就是这么补的，因为 hf-mirror 5.7 MB/s 比排查 UI 更快）。

### 坑 6 · wikiextractor 3.1 改了输出文件名

**现象**：清洗阶段读到 0 篇，`funnel.json` 里 `raw=0`，但抽取日志显示成功。

**根因**：3.0.x 输出 `wiki_00`、`wiki_01`…；**3.1.0 输出 `AA`、`AB`…**。任何 `glob("wiki_*")` 都会静默读到空。

**解法**：不要按文件名过滤，按"目录下所有文件"读：

```python
return sorted(p for p in root.rglob("*") if p.is_file() and not p.name.startswith("."))
```

### 坑 7 · MinHash 太慢

**现象**：28 万篇文档、每篇上千字符 → 3 亿个 5-gram，逐条 `update` 要 1 h+，整条流水线卡在去重。

**解法**：① 每篇确定性抽样 **512** 个 shingle；② 用 `update_batch`（内部向量化）。去重从 1 h+ 降到 **2 分钟**，判定质量几乎不变（MinHash 本来就是抽样估计）。

## 3. 省钱的六条纪律

| # | 纪律 | 省下 |
|---|---|---|
| 1 | 数据和代码一律放 `/root/autodl-tmp`（数据盘），系统盘只 30 GB | 避免扩容费 |
| 2 | 取数/装依赖用**无卡模式**，只有训练才开卡 | ~¥2/次 |
| 3 | 长跑前一定先跑 **20 步冒烟**（2 分钟） | 避免 2 小时白跑 |
| 4 | 用 `--time-budget-min` 给每次运行封顶 | 避免无限烧 |
| 5 | 用 `chain.sh` 自动接力，人不用守着 | 避免空转 |
| 6 | 每步都幂等（输出存在就跳过），中断直接重跑 | 避免重算 |

## 4. 如果只有 ¥10

按这个顺序砍：

1. 只跑 **125M**（¥1.6），跳过 360M（省 ¥3.6）；
2. 语料预算从 180M 字符降到 90M（village 减半，训练 25 min，省 ¥0.8）；
3. SFT 只跑 1 epoch（省 ¥0.6）；
4. **绝对不要**让实例空转——那比上面所有加起来都贵。

最低配版本（125M + 90M tokens + 1 epoch SFT）实测约 **¥2.5**，仍然能拿到一个会写中文的模型和完整的续训验证。
